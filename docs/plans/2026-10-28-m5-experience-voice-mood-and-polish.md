# M5: Experience, Voice, Mood and Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** It looks and feels like the brief: a calm four-screen onboarding that draws Dad's own business with Muse Image, a home screen asking "What do you want to achieve today?", push-to-talk with Muse Voice Transcribe, a soothing design mode (faded generated backgrounds, ambient sound, chimes), three themes with larger text, "explain anything", inbox triage running locally on Muse Glimmer, and a repo ready for judges.

**Architecture:** Mostly web app work on top of M1–M4. The server adds a settings store, a business profile, mood image generation, an explain endpoint, a WebSocket proxy to the Meta realtime transcription endpoint (the browser never holds the API key), and a second OpenAI-compatible provider for Glimmer behind the `triage` role.

**Tech Stack:** M4 stack plus `@fontsource-variable/inter`, `@fontsource-variable/nunito`, and the Web Audio API (AudioWorklet) for 24 kHz PCM capture. No sound library: use `HTMLAudioElement`.

**Spec:** `AgenticHarness/docs/meta-ai-hackathon-my-dads-ai-agent/plans/2026-10-28-dads-ai-agent-design.md` (sections 3 model use, 4 mood, 6 voice, 9, 11 cut line, 12 demo script).

**Depends on:** M1–M4. Uses `Gateway`, `createImageModels.generate`, `createFileStore`, `useAgent`, `AgentPanel` (mic placeholder), `DesignView` `onBuilt` hook, `ModeSwitch`, views (`GET /api/views`), `registerEmailTrigger` triage call, `PUT /api/settings`.

## Global Constraints

- All earlier global constraints still apply.
- Copy is fixed where the spec fixed it:
  - Onboarding screen 1: "Technology has made running a business harder, not easier. That's not your fault." Button: "Let's fix that."
  - Screen 3: "You've kept a business running through all of it. That's the hard part."
  - Home: "What do you want to achieve today?"
- Themes:
  - **Morning:** default, from M2.
  - **Evening:** soft dark.
  - **Workshop:** high contrast, base font 20px.

  Text size setting: Normal 17px / Large 19px / Extra large 21px, independent of theme.
- Fonts: Inter (interface) and Nunito (headings, home prompt, onboarding), self-hosted via fontsource (no network fonts).
- Sound is off until Dad interacts once (browser autoplay rules). Default volume 0.25, fades in over 2 s. Mute and volume are in Settings and in a small control in design mode. Runtime mode is silent.
- Design-mode backdrop: opacity 0.16 (Evening 0.10), a 60 s slow drift, a crossfade every 45 s. It's static when `prefers-reduced-motion` is set.
- Desktop only: below 1280 px viewport width, show the full-screen message "This works best on a bigger screen. Try a laptop or desktop."
- Every asset is either generated by Muse Image during the event or CC0 audio from freesound.org (filtered to the CC0 license), with every file listed in `ASSETS.md` (file, source URL, licence, author).
- Glimmer: `GLIMMER_BASE_URL` (e.g. `http://127.0.0.1:1234/v1` for LM Studio) and `GLIMMER_MODEL`. When either is unset or the health check fails, `triage` uses `muse-spark-1.3`.

## Review Focus

- Microphone permission denied or no microphone: the mic button shows "I can't hear you. Check your microphone in Chrome's settings." and typing still works (test in Task 3).
- Transcription returns an empty transcript (Dad pressed and said nothing): nothing is sent to the agent, and a hint "I didn't catch that. Try again?" appears (test in Task 3).
- Muse Image fails or is slow during onboarding: onboarding continues with the bundled backgrounds after 20 s, and the generated set replaces them when ready (test in Task 4).
- Glimmer is configured but LM Studio isn't running: the server starts, triage falls back to Spark, and Settings shows "Inbox sorting is using Muse Spark (Glimmer isn't running on this computer)." (test in Task 7).
- Workshop theme with Extra large text: the canvas boxes and agent panel don't overflow or clip at 1280×800 (test in Task 1 as a visual check list item and a unit test on computed sizes).

### Task 3: Push-to-talk with Muse Voice Transcribe

**Files:**
- Create: `apps/server/src/voice/proxy.ts`; modify `apps/server/src/app.ts` (`/api/voice` WebSocket)
- Create: `apps/web/src/voice/{pcm-worklet.js,useVoice.ts,MicButton.tsx}`
- Modify: `apps/web/src/agent/AgentPanel.tsx` (wire MicButton)
- Test: `apps/server/test/voice-proxy.test.ts`, `apps/web/src/voice/useVoice.test.ts`, `apps/web/src/voice/MicButton.test.tsx`

**Interfaces:**
- Produces:
  - **Server `/api/voice`:**
    1. Accepts a browser WebSocket and opens `wss://api.meta.ai/v1/asr/realtime`.
    2. Sends the handshake frame with the server's `MODEL_API_KEY`, `model: 'muse-voice-transcribe-1.0'` and mode `ENDPOINTING` (field names per https://dev.meta.ai/docs/api-reference/voice/realtime).
    3. Forwards binary PCM frames up, and maps server events down to `{ type: 'partial', text } | { type: 'final', text } | { type: 'speechEnd' } | { type: 'error', message }`.
    4. On a browser `{ type: 'stop' }` it sends `{"type":"endStream"}` and closes once the final transcript arrives.
  - `useVoice(): { state: 'idle'|'listening'|'thinking'|'error'; partial: string; error?: string; start(): Promise<void>; stop(): void; onFinal(cb: (text: string) => void): void }`.
    - **Capture:** `getUserMedia({ audio: { channelCount: 1 } })` → AudioWorklet resamples to 24 kHz mono 16-bit PCM → sends 100 ms frames.
    - **Stopping:** it stops automatically on `speechEnd` (end-of-speech detection) or when the button is released or clicked again.
  - **MicButton:** a large round button (64 px) with "Hold to talk" (hold or click to toggle). While listening it shows a pulsing ring and the live `partial` text. On final with non-empty text it calls `send(text)` in the agent panel. Empty final → hint "I didn't catch that. Try again?". Permission error → "I can't hear you. Check your microphone in Chrome's settings."

- [ ] **Step 1: Write failing tests.**
  - Proxy, with a fake upstream WS server: it receives the handshake with `model: 'muse-voice-transcribe-1.0'` and the key, forwards a binary frame unchanged, and maps an upstream transcript event to `{type:'final'}`.
  - useVoice: `getUserMedia` rejecting with `NotAllowedError` gives state `error` and the microphone message.
  - MicButton: an empty final doesn't call `send` and shows the hint.
- [ ] **Step 2: Run them; expect FAIL.**
- [ ] **Step 3: Implement.** Worklet resampling uses linear interpolation from `sampleRate` to 24000, then clamps and converts to Int16.
- [ ] **Step 4: Run them; expect PASS. Manually: say "When a customer emails me, save them and draft a reply." The partial text appears live, it stops by itself after you finish, and the agent receives the sentence.**
- [ ] **Step 5: Commit** `feat: push-to-talk via Muse Voice Transcribe realtime, proxied through the server`
